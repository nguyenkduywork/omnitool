# omnitool Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. §3 of this document is the binding contract — do not redefine any type in it.

**Goal:** Ship a 100% client-side, open-source web app for everyday file operations (merge PDFs, merge/convert images, zip, hash, convert data) that is measurably fast and trivial to extend.

**Architecture:** A tool registry plus a Web Worker pipeline. The shell sniffs file types, filters the registry to applicable tools, and runs the chosen tool's lazily-imported "op" in a worker. All format knowledge lives in `src/tools/**/*.op.ts` behind one function signature. No framework, no server.

**Tech Stack:** TypeScript, Vite, vanilla DOM, anime.js v4, pdf-lib, pdfjs-dist, fflate, qrcode. Tests: vitest (unit) + Playwright (e2e).

**Spec:** `docs/superpowers/specs/2026-08-29-omnitool-design.md`

---

## 1. Global Constraints

Every task's requirements implicitly include this section.

- **Node** ≥ 20. **Package manager:** npm. **Module system:** ESM only (`"type": "module"`).
- **TypeScript strict mode on.** No `any` in committed code; no `@ts-ignore` without a one-line justification comment.
- **No file may leave the device.** Zero network calls at runtime. No analytics, no telemetry, no CDN fetches, no fonts from remote hosts.
- **Size budgets (CI-enforced, build fails on breach):** initial JS ≤ 40 KB gzip; initial CSS ≤ 12 KB gzip; total first-paint transfer ≤ 60 KB gzip.
- **Import rules (ESLint-enforced):**
  - `src/tools/**` may import **only** from `src/types.ts` and its declared npm engine — never from `src/core/**` or `src/ui/**`.
  - `src/core/**` must never import from `src/ui/**`.
  - Only `src/ui/motion.ts` may import `animejs`.
- **Ops are DOM-free.** No `window`, `document`, or `HTMLElement` inside `src/tools/**`. They run in a worker.
- **Animation touches only `transform` and `opacity`.** Never animate layout properties.
- **`prefers-reduced-motion: reduce` disables all motion.** Functionality must never depend on animation completing.
- **Honest reporting.** No tool may claim an outcome it did not achieve. `pdf-shrink` reports real before/after bytes and is labelled "Re-encodes images inside the PDF".
- **Licence:** MIT.
- **Commit style:** Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).

## 2. The TDD cycle (binding, applies to every task)

Stated once instead of repeated per task. Every task follows it:

1. Write the failing test(s) first, in the task's named test file.
2. Run them; confirm they fail **for the intended reason** (not an import typo).
3. Write the minimal implementation.
4. Run `npm run test -- <file>`; confirm pass.
5. Run `npm run typecheck && npm run lint`; confirm clean.
6. Commit with a Conventional Commit message.

**Every op, without exception, must have tests covering all four of:** happy path; corrupt/invalid input raising the correct `OpErrorCode`; cancellation part-way through via `AbortSignal`; and `onProgress` being called and monotonically non-decreasing, ending at 1.

A task is not complete until `npm run typecheck`, `npm run lint`, and `npm run test` all pass. Do not report success without having run them and seen the output.

## 3. The shared contract — `src/types.ts`

**This file is canonical. Task 1 creates it verbatim. No other task may modify it** — if a task believes it needs a change here, it must stop and report that instead of editing.

```ts
// src/types.ts — dependency-free. Imports nothing. Imported by core/, ui/, tools/.

export type OpInput  = { name: string; type: string; buffer: ArrayBuffer };
export type OpOutput = { name: string; type: string; buffer: ArrayBuffer };

export type OpContext = {
  /** Report progress in the range 0..1. Must be called at least once per input. */
  onProgress(fraction: number): void;
  signal: AbortSignal;
};

export type Op = (
  inputs: OpInput[],
  options: Record<string, unknown>,
  ctx: OpContext,
) => Promise<OpOutput[]>;

export type OpErrorCode =
  | 'UnsupportedFormat'
  | 'CorruptFile'
  | 'TooLarge'
  | 'EncoderUnavailable'
  | 'InvalidOptions'
  | 'Cancelled'
  | 'OutOfMemory';

export class OpError extends Error {
  constructor(
    public readonly code: OpErrorCode,
    message: string,
    public readonly file?: string,
  ) {
    super(message);
    this.name = 'OpError';
  }
}

export type OptionDef =
  | { kind: 'select'; label: string; choices: { value: string; label: string }[]; default: string }
  | { kind: 'number'; label: string; min: number; max: number; step: number; default: number }
  | { kind: 'range';  label: string; min: number; max: number; step: number; default: number }
  | { kind: 'toggle'; label: string; default: boolean }
  | { kind: 'text';   label: string; placeholder?: string; default: string };

export type OptionSchema = Record<string, OptionDef>;

export type ToolGroup = 'pdf' | 'image' | 'data';

/** Renders a bespoke options editor. Returns a teardown function. */
export type ToolEditor = (
  mount: HTMLElement,
  inputs: File[],
  onChange: (options: Record<string, unknown>) => void,
) => () => void;

export type ToolDef = {
  id: string;
  name: string;
  blurb: string;
  group: ToolGroup;
  /** Mime types, or the wildcards 'image/*' / '*'. */
  accepts: string[];
  minInputs: number;
  /** null means unbounded. */
  maxInputs: number | null;
  options?: OptionSchema;
  editor?: () => Promise<{ default: ToolEditor }>;
  load: () => Promise<{ default: Op }>;
};

/** Per-input outcome. A job reports partial success honestly. */
export type FileResult =
  | { status: 'ok'; name: string }
  | { status: 'failed'; name: string; code: OpErrorCode; message: string };

export type JobResult = {
  outputs: OpOutput[];
  results: FileResult[];
  /** True when at least one input failed but others succeeded. */
  partial: boolean;
};

export type Job = {
  readonly id: string;
  onProgress(cb: (fraction: number) => void): void;
  cancel(): void;
  readonly done: Promise<JobResult>;
};
```

### 3.1 Worker message protocol (canonical)

```ts
// main -> worker
type RunMessage = {
  kind: 'run';
  jobId: string;
  toolId: string;
  inputs: OpInput[];                    // buffers TRANSFERRED, not cloned
  options: Record<string, unknown>;
};
type CancelMessage = { kind: 'cancel'; jobId: string };

// worker -> main
type ProgressMessage = { kind: 'progress'; jobId: string; fraction: number };
type DoneMessage     = { kind: 'done'; jobId: string; outputs: OpOutput[]; results: FileResult[] };
type ErrorMessage    = { kind: 'error'; jobId: string; code: OpErrorCode; message: string; file?: string };
```

## Task 2 — The kernel  *(M1)*

**Files:** Create `src/core/format.ts`, `src/core/registry.ts`, `src/core/pipeline.ts`, `src/core/fs.ts`, `src/core/workers/pool.ts`, `src/core/workers/runner.worker.ts`

**Consumes:** everything in §3.
**Produces:**
```ts
// format.ts
export function sniffType(buffer: ArrayBuffer, filename: string): string; // mime, or 'application/octet-stream'
export function label(mime: string): string;                              // 'PDF document'
export function accepts(tool: ToolDef, mimes: string[]): boolean;
// registry.ts
export const TOOLS: ToolDef[];
export function getTool(id: string): ToolDef | undefined;
export function toolsFor(mimes: string[]): ToolDef[];
// pipeline.ts
export function run(toolId: string, files: File[], options: Record<string, unknown>): Job;
// fs.ts
export function readFiles(files: File[]): Promise<OpInput[]>;
export function download(output: OpOutput): void;
export function downloadBundle(outputs: OpOutput[], zipName: string): Promise<void>;
// pool.ts
export function acquire(): Promise<PooledWorker>;
export function release(w: PooledWorker): void;
export function size(): number;
```

- [ ] `format.ts`: sniff by **magic bytes, not extension** — `%PDF-`, `\x89PNG`, `\xFF\xD8\xFF` (JPEG), `RIFF....WEBP`, `....ftypavif`, `PK\x03\x04` (zip), `GIF8`. Fall back to extension, then `application/octet-stream`. Wildcards `image/*` and `*` handled in `accepts`.
- [ ] `pool.ts`: size = `Math.max(1, Math.min(navigator.hardwareConcurrency ?? 4, 8) - 1)`. Lazy worker creation. **Transfer** `ArrayBuffer`s (pass the transfer list); never structured-clone them. On worker `error`/`messageerror`, terminate it, remove it from the pool, create a replacement, and reject only that worker's in-flight job with `OutOfMemory`.
- [ ] `runner.worker.ts`: on `RunMessage`, resolve the op via a **static id→loader map** (a `switch` or object literal referencing `import()` calls directly — Vite cannot code-split a dynamic template string, so this map must be literal), then execute with an `OpContext` that posts `ProgressMessage`s throttled to at most one per 50 ms plus a guaranteed final `1`.
- [ ] `pipeline.ts`: `run()` returns a `Job` immediately. **Per-file failure, not per-job** — one bad input yields `partial: true`, the good outputs, and a `failed` entry naming the file. `cancel()` posts `CancelMessage`; if the worker has not settled within 2000 ms, terminate and replace it.
- [ ] `registry.ts`: metadata + `load` thunks only. **No logic beyond array lookups.** Register only `pdf-merge` in this task; later tasks append their own entries.
- [ ] `pdf-merge` end-to-end under vitest: merge `small.pdf` twice, assert the output has 6 pages. This proves the kernel headlessly before any UI exists.
- [ ] Tests: sniffing each fixture to the right mime; `accepts` wildcard behaviour; progress monotonicity; cancellation resolving as `Cancelled`; a deliberately throwing op producing `partial: true` rather than a rejected job.
- [ ] Verify and commit.

## 5. Execution order and parallelism

```
Task 1 (scaffold + contract)            <- must finish first; everything depends on it
      |
      +-- Task 2 (kernel)               <- Tasks 3/4/5 need only types.ts + deps,
      +-- Task 3 (PDF tools)               so they run CONCURRENTLY with Task 2
      +-- Task 4 (image tools)
      +-- Task 5 (data tools)
      |
      +-- Task 6 (UI shell)             <- needs Task 2's registry/pipeline exports
            |
            +-- Task 7 (palette, PWA)
            +-- Task 8 (docs, e2e, deploy)
```

**Shared-file contention:** Tasks 2–5 all append to `src/core/registry.ts` and the runner's id→loader map. To avoid concurrent-edit conflicts, Tasks 3, 4, and 5 each write their entries to a **separate** module — `src/core/registry.pdf.ts`, `registry.image.ts`, `registry.data.ts`, each exporting `ToolDef[]`, and a matching `loaders.pdf.ts` / `loaders.image.ts` / `loaders.data.ts` exporting `Record<string, () => Promise<{default: Op}>>`. `registry.ts` and `runner.worker.ts` merely concatenate them. This keeps the manifest split by owner and makes parallel work conflict-free.
